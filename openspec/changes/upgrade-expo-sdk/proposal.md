# Proposal

## Why

The mobile app is on Expo SDK 52 / React Native 0.76. The latest is Expo SDK 58 / React Native 0.88, released 2026-10-15, so the app is six SDKs behind. Every SDK we skip makes the eventual upgrade harder. Old SDKs stop getting fixes and stop keeping up with Play target-API requirements. The new Expo Modules features and New Architecture-only libraries also need a current SDK. Since React Native 0.82 the legacy architecture is gone, so we have to enable the New Architecture; we currently run with `newArchEnabled=false`.

## What Changes

- Upgrade `mobile/` one SDK at a time: 52 → 53 → 54 → 55 → 56 → 57 → 58. Each step gets its own commit with dependencies aligned via `npx expo install --fix`.
- **BREAKING (build):** enable the React Native New Architecture. Every native dependency must support it, especially `react-native-ble-plx`, which NIIMBOT label printing depends on.
- Bump React, React Native, React Navigation and all `expo-*` packages to the versions SDK 58 expects.
- Re-evaluate the `expo-build-properties` `kotlinVersion: 1.9.25` pin. Remove it unless a dependency still needs it.
- Update the CI toolchain (Node, JDK, Android SDK) in `.github/workflows/android.yml` if SDK 58 requires it.
- Fix any code broken by API changes across these SDKs (camera, file system, edge-to-edge layout, navigation).
- No user-facing behavior changes. Scanning, capture, BLE printing and APK distribution must work exactly as before.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

None. This is a platform/tooling upgrade with no spec-level behavior change (`skip_specs: true`). The existing specs for `label-scanning`, `item-capture`, `printer-*`, `print-*` and `apk-distribution` are the regression contract the upgrade must keep passing.

## Impact

- **Code:** `mobile/package.json`, `mobile/package-lock.json`, `mobile/app.json`, and any `mobile/src/**` files hit by API changes (mainly `Scanner.tsx`, `Capture.tsx`, and `niimbot/ble.ts` / `transport.ts`).
- **Native:** `mobile/android/` is gitignored and regenerated by `expo prebuild`, so there are no committed native edits to migrate. Config plugins in `app.json` must still work on SDK 58.
- **CI:** `.github/workflows/android.yml` (toolchain versions). The APK URL and release flow don't change.
- **Dependencies:** `react-native-ble-plx` (New Architecture compatibility is the main risk), `react-native-screens`, `react-native-gesture-handler`, `react-native-safe-area-context`, AsyncStorage, React Navigation 7.x.
- **Out of scope:** iOS, EAS Build/Update adoption, and UI changes.
